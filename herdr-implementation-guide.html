Herdr v0.8.2 기준 · 사내망 v0.1

Herdr를 실행 계층으로 쓰는 AI 개발 운영 가이드

GitHub가 일의 기록을, Skill이 절차를, Serena가 코드 탐색을 맡고, Herdr는 Worktree와 Codex·OpenCode 프로세스를 실제로 실행하고 관찰한다.

권장 동시 실행: Coordinator 1 + Builder 최대 2 초기 자동화: Skill + 결정적 스크립트 초기 제외: Marketplace plugin, 자동 승인, 자동 main merge
핵심 판단 역할 구조 Workspace 구성 사내망 설치 초기 설정 실행 흐름 자동화 구조 한계와 안전 도입 순서 출처

1. 핵심 판단

Herdr는 에이전트 자체도, GitHub 프로젝트 관리자도 아니다. 실제 터미널 프로세스를 보존하고 여러 에이전트의 상태를 한 화면에 모으며 CLI와 로컬 socket으로 제어하는 멀티플렉서다.

Source of work

GitHub

Issue, Project, PR, review, merge와 배포 승인의 기준점.

Policy

Agent Skill

계획, 분할, 테스트 위험도, Worktree 배치, 리뷰 절차.

Runtime

Herdr

Workspace, pane, agent 실행, 상태, 대기, 출력 수집.

Code context

CODEMAP + Serena

사람용 구조 지도와 심볼·참조 기반 코드 탐색.

권장 결론 Herdr를 기존 Planner·Coordinator·Builder·Reviewer 모델의 실행 기반으로 사용한다. GitHub 상태와 Herdr의 working / blocked / done / idle 상태는 동기화하지 않고 서로 다른 정보로 취급한다.
범위 주의 Herdr가 pane 안에서 실행·관찰하는 대상은 Codex CLI와 OpenCode CLI 프로세스다. Codex 데스크톱 앱의 Task를 Herdr Workspace로 가져오거나 제어하는 구조로 이해하면 안 된다.

2. 전체 역할 구조

v0.1에서는 별도 Planner 프로세스를 늘리지 않는다. 하나의 Control Agent가 계획과 조정을 맡고, 독립성이 확인된 Task만 두 Builder에게 보낸다. Reviewer는 Builder 완료 후 순차적으로 실행한다.

3. Repository 하나의 Workspace 구성

Herdr의 Workspace는 프로젝트·Task·조사를 담는 최상위 컨테이너다. Git Worktree는 원본 Workspace 아래 묶인 자식 Workspace로 표시된다.

project-a · canonical checkout · Control Agent · 읽기 중심
issue-123-integrationcodex/123-integration
통합과 Reviewer 전용
issue-123-apicodex/123-api
Builder A · 허용 경로: API
issue-123-datacodex/123-data
Builder B · 허용 경로: data
Named session

완전히 다른 생활 영역만 분리

work와 personal처럼 socket·pane·runtime state를 분리해야 할 때만 named session을 사용한다. 프로젝트 분리는 먼저 Workspace로 해결한다.

Tabs

한 Workspace 안의 관점

agentverifyserverlogs 정도만 둔다. Task마다 tab을 과도하게 늘리지 않는다.

4. 사내망 설치 원칙

공식 설치 스크립트는 인터넷에서 바이너리를 내려받는다. 사내망에서는 검토한 release를 내부 저장소에 보관하고 고정 버전을 배포한다.

Version

v0.8.2 고정

이 가이드는 공식 stable v0.8.2 문서와 release-matched Skill을 기준으로 한다.

License

Apache-2.0 확인

v0.8.2 tag의 LICENSE를 내부 패키지에 함께 보존한다.

Distribution

내부 mirror

Linux/macOS/Windows asset 또는 내부에서 빌드한 바이너리와 해시를 배포한다.

curl | sh를 사내 표준 절차로 만들지 않는다 인터넷이 되는 검토 환경에서 release asset과 LICENSE를 가져와 보안 검토 후 내부 artifact registry에 올린다. 운영 host에는 내부 주소에서만 설치한다.

권장 실행 위치

코드와 credential이 있는 Linux 개발 host에서 Herdr server를 실행하고, 사용자는 일반 SSH 후 herdr session attach work로 접속한다. Herdr 자체 웹 대시보드나 중앙 SaaS는 필요 없다.

remote development host
ssh dev-host
cd /srv/repos/project-a
herdr session attach work

Windows는 로컬 사용이 가능하지만 공식 문서상 herdr --remote의 remote host로는 지원되지 않는다. 원격 실행 host는 Linux/macOS로 잡는 편이 안전하다.

5. 최소 초기 설정

Herdr는 설정 없이도 동작한다. 아래 항목만 명시해 사내망, Worktree, 복구와 보안 동작을 분명하게 만든다.

~/.config/herdr/config.toml
onboarding = false

[server]
headless_cols = 160
headless_rows = 50

[worktrees]
directory = "~/work/herdr-worktrees"

[session]
resume_agents_on_restore = true

[experimental]
# terminal output에는 token과 prompt가 포함될 수 있다.
pane_history = false

[update]
# 폐쇄망에서는 버전·탐지 규칙을 내부에서 검토해 수동 갱신한다.
version_check = false
manifest_check = false

[keys]
# herdr --remote 사용 시 local image clipboard가 remote로 전달되는 단축키를 끈다.
remote_image_paste = ""

[ui]
status_indicators = "symbols"

[ui.toast]
delivery = "herdr"
delay_seconds = 1
Codex integration

session restore용 hook

Codex 통합은 session identity를 보고하지만 상태는 screen manifest로 판단한다. 설치 시 Codex의 hooks.json과 config.toml을 수정하므로 diff를 검토한다.

review before rollout
herdr integration install codex
herdr integration status
OpenCode integration

lifecycle + session plugin

OpenCode 통합은 ~/.config/opencode/plugins/herdr-agent-state.js를 설치하고 lifecycle과 session identity를 보고한다.

review before rollout
herdr integration install opencode
herdr integration status

공통 Herdr Skill

공식 release-matched Skill을 .agents/skills/herdr/SKILL.md에 고정해 Codex와 OpenCode가 공유한다. 인터넷 기반 npx skills 대신 설치된 바이너리가 제공하는 사본을 검토한다.

release-matched skill inspection
herdr --skill
중요한 공식 guardrail Herdr Skill은 HERDR_ENV=1이 없으면 제어를 중단하도록 규정한다. Control Agent는 반드시 Herdr가 관리하는 pane 안에서 실행한다.

6. Issue 하나를 구현하는 실제 흐름

아래는 Parent Issue #123을 두 개의 독립 Task로 나누어 병렬 구현한 뒤 integration PR 하나로 만드는 예다.

계획과 병렬성 판정

Control Agent가 Issue, CONTEXT.md, CODEMAP.md, ADR을 읽고 Serena로 관련 심볼·참조를 확인한다. 수정 경로가 겹치지 않고 선후 관계가 없는 Task만 병렬로 표시한다.

integration과 Task Worktree 생성

Herdr의 Worktree 명령은 checkout을 만들고 자식 Workspace로 연다. branch 이름은 기존 Git 규칙을 따른다.

각 Worktree에서 Builder 시작

하나의 Worktree에는 하나의 구현 agent만 둔다. Codex와 OpenCode를 섞을 수 있지만 동일 Task를 동시에 수정하게 하지 않는다.

명시적인 Task packet 전달

Issue, 기준 commit, 허용 경로, 금지 경로, 수용 조건, 검증 명령, commit·보고 형식을 prompt에 포함한다.

상태와 결과 수집

agent wait에 timeout을 넣고, blocked면 화면을 읽은 뒤 사람에게 판단을 요청한다. 완료 판정은 화면 상태만이 아니라 commit SHA와 검증 결과로 한다.

integration, Reviewer, 사람 승인

Coordinator가 Task branch를 integration branch에 합치고 전체 검증을 실행한다. Reviewer가 통합 diff를 검토한 뒤 PR을 만들며 main merge와 production 배포는 사람이 승인한다.

Worktree 생성 예시

Herdr worktree CLI
herdr worktree create \
  --cwd /srv/repos/project-a \
  --branch codex/123-integration \
  --base main \
  --label issue-123-integration \
  --no-focus

herdr worktree create \
  --cwd /srv/repos/project-a \
  --branch codex/123-api \
  --base codex/123-integration \
  --label issue-123-api \
  --no-focus

herdr worktree create \
  --cwd /srv/repos/project-a \
  --branch codex/123-data \
  --base codex/123-integration \
  --label issue-123-data \
  --no-focus

자동화에서는 반환 JSON에서 Workspace와 pane ID를 읽는다. 예시의 ID나 sidebar 순서를 추측하지 않는다.

Agent 시작과 대기 예시

explicit IDs, names and timeouts
# 먼저 해당 Worktree workspace의 root pane ID를 조회한다.
herdr pane list --workspace <workspace-id>

herdr agent start builder_api \
  --kind codex \
  --pane <pane-id>

herdr agent prompt builder_api \
  "$(cat /path/to/task-packet.md)" \
  --wait \
  --timeout 1800000

herdr agent get builder_api
herdr agent read builder_api --source recent-unwrapped --lines 120

- src/api/**
- tests/api/**

- database migrations
- shared public interfaces

2. ...

- <type or lint command>

7. Skill·Script·Plugin의 배치

공식 herdr Skill은 CLI 사용법을 가르친다. 우리 정책은 별도의 얇은 Skill에 두고, Worktree·검증·결과 파일 생성은 결정적 스크립트로 만든다.

recommended repository layout
.agents/skills/
├── herdr/                       # upstream v0.8.2, 수정 최소화
│   ├── SKILL.md
│   └── UPSTREAM.md              # source URL, tag, license, checksum
└── orchestrate-with-herdr/      # 우리 운영 정책
    ├── SKILL.md
    ├── references/
    │   ├── task-packet.md
    │   └── role-permissions.md
    └── scripts/
        ├── dispatch-task
        ├── collect-result
        └── check-worktree-state
Skill

판단과 절차

언제 병렬화하는지, 최대 Worker 수, 승인 경계, prompt 형식, 완료 조건.

Script

결정적인 실행

JSON ID 파싱, branch·path 검증, Worktree 생성, timeout, 결과 수집.

Plugin

반복 후 승격

같은 흐름이 충분히 안정된 뒤 Herdr action이나 worktree.created event로 포장.

v0.1에서는 Herdr plugin을 만들지 않는다 Herdr plugin은 일반 사용자 권한으로 실행되고 전체 Herdr CLI와 환경에 접근하며 별도 sandbox가 없다. 먼저 저장소에 versioned script로 흐름을 검증한 뒤, 반복 가치가 확인될 때만 내부 plugin으로 승격한다.

8. 반드시 알아야 할 한계와 안전 규칙

State

상태는 완료 증명이 아니다

done과 idle은 agent terminal의 lifecycle 상태다. 테스트 통과, commit 생성, 요구사항 충족을 뜻하지 않는다. unknown도 성공이 아니다.

Blocked

자동 승인 금지

Codex 상태는 screen manifest 기반이라 낯선 승인 UI가 idle로 보일 수 있다. blocked가 나오면 내용을 읽고 사람이 결정하며 자동으로 Enter를 보내지 않는다.

Persistence

detach와 restart는 다르다

detach하면 원래 프로세스가 계속 실행된다. Herdr server가 완전히 재시작되면 임의 process는 사라지고 layout만 복구된다. 공식 integration이 보고한 Codex/OpenCode session만 native resume 대상이 될 수 있다.

Waiting

항상 timeout 지정

Herdr wait 명령에는 기본 timeout이 없다. 자동화에서는 반드시 timeout을 넣고 timeout·blocked·unknown을 각기 다른 실패 상태로 처리한다.

Secrets

pane history 비활성

pane output에는 token, prompt, command 결과가 들어갈 수 있다. screen history 저장은 기본적으로 끈 상태를 유지하고 Herdr config/state 디렉터리를 terminal history와 같은 민감도로 취급한다.

Deletion

강제 Worktree 제거 제한

dirty Worktree의 --force 제거, session stop, pane close는 사람이 대상을 확인한 뒤에만 한다. branch는 Herdr가 자동으로 삭제하지 않는다.

Control Agent 금지 행동 사람 승인 없이 herdr server stop, 다른 사용자가 만든 pane/workspace 종료, blocked dialog 응답, dirty Worktree 강제 제거, main merge, production 배포를 수행하지 않는다.

9. 복잡도를 억제하는 도입 순서

Week 1

수동 멀티플렉서

  • 내부 mirror에서 v0.8.2 설치
  • 한 repo, 한 Workspace
  • Worktree 1개와 Builder 1개
  • detach·reattach와 상태 표시 경험
Week 2

두 Builder 병렬화

  • Codex/OpenCode integration 검토 설치
  • 공식 Herdr Skill 고정
  • Task packet 표준화
  • 독립 Task만 최대 2개 실행
Week 3+

결정적 자동화

  • orchestrate-with-herdr Skill
  • dispatch·collect script
  • timeout·blocked 처리
  • 반복성이 증명된 뒤만 plugin 검토

v0.1 완료 체크리스트

  • Herdr version, LICENSE, binary hash가 내부 artifact registry에 기록돼 있다.
  • Codex/OpenCode integration이 수정하는 사용자 설정 파일을 검토했다.
  • .agents/skills/herdr가 설치된 binary tag와 일치한다.
  • 한 Worktree에 구현 agent 하나만 실행한다.
  • 병렬 Builder는 최대 2개이며 파일·모듈 경계가 겹치지 않는다.
  • 모든 wait 명령에 timeout이 있다.
  • Builder 결과는 commit SHA와 검증 결과로 확인한다.
  • main merge, production deploy, 승인 dialog는 사람에게 남겨둔다.
