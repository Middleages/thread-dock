# 프로젝트 진행·문맥 회수·문서화를 MVP의 중심으로 둔다

## 배경

이전 작업은 test pilot과 장애 검증에 과도한 자원을 사용했다.
사용자는 실사용하면서 개선할 수 있는 MVP로 재시작하고,
기존 파일럿 Run의 실행 호환성은 요구하지 않기로 했다.
여러 프로젝트를 오갈 때 문맥을 회수하고, 시작 이유·구현 방향·결정 이력을 남기는 것이 목적이다.
프로젝트는 하나 또는 여러 저장소이며 Monitor, Projects와 Wiki가 함께 필요하다.

## 결정

1. Project, Repository, Work Item, Repository Run과 Task를 분리한다.
2. 대표 저장소의 Parent Issue에 저장소별 PR과 전체 완료 조건을 연결한다.
3. Monitor 목록·상세, Projects와 Wiki를 MVP에 포함한다.
4. 목적·최근 결정·현재 상태·다음 행동을 evidence와 함께 handoff로 남긴다.
5. 새 작업의 재개와 제한된 자동 수정·재검토를 지원한다.
6. 모든 PR은 사람이 병합하며 여러 저장소의 부분 병합을 표시한다.
7. 필수 코드 결과·문서·업무 기록 발행이 끝나야 전체 업무를 완료한다.
8. 기존 v1 실행 호환성을 제외하고 필요한 코드만 재사용한다.
9. 혼동되는 옛 설계·계획은 현재 tree에서 삭제하고 Git history를 과거 근거로 남긴다.

승인 근거는 2026-09-07 설계 검토 대화의 요구사항 확인과 “좋아. 해보자”,
이어진 “혼동이 생길 수 있는 게 있다면 과감히 지워도 좋음”이다.
공유 가능한 대화 URL이 없으므로 approval URL을 생성하지 않는다.
호출 한도 2, Task 수정 2회, 일시 실패 재시도 1회와 merge-commit 지원은 설계 기본값이며
각 수치를 사용자가 별도로 지정한 것으로 기록하지 않는다.

## 대안과 이유

| 대안 | 평가 |
|---|---|
| adapter와 PR 준비만 제공 | 프로젝트 전환·결정 기록·문서 요구를 충족하지 못한다. |
| 기존 v1·파일럿 체계 전체 유지 | 호환성과 실패 인증이 다시 실사용을 늦출 수 있다. |
| 프로젝트 중심 흐름과 작은 실행·문서 도구 | 사용자 업무의 전체 흐름을 먼저 검증할 수 있어 선택한다. |

## 기존 결정에 미치는 영향

- ADR 0003의 일반 변경 자동 병합을 폐기한다.
- ADR 0002의 CLI transport를 유지하고 단일 active run 가정을 폐기한다.
- ADR 0001의 Go/Wails를 유지하고 자동 업데이트는 후속 범위로 둔다.
- ADR 0004의 검증 원칙을 새 Task·전체 업무 gate에 맞춘다.
- ADR 0005의 실행 종료·근거 삭제 분리만 유지하며 Codex 배제와 v1 상태 기계 유지 의무는 없다.

현재 코드가 이 정책을 이미 구현했다고 주장하지 않는다.
[현재 설계](../superpowers/specs/2026-09-07-project-workflow-mvp-design.md)가 상세 기준이다.
[이전 커밋](https://github.com/Middleages/thread-dock/tree/f669ec6008ee3ccc14d688aad83700a1da84fceb)은 과거 자료다.
