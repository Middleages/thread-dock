# ThreadDock Windows Monitor, Actions and Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Windows 11 ThreadDock Monitor that reads `agentctl`, renders the approved News Desk interface, observes and dispatches GHES Actions, and updates safely through GHES Releases.

**Architecture:** Wails binds a small Go application interface to React. The Windows backend invokes `wsl.exe` with structured arguments, owns the production GHES credential and exposes typed status/actions to the frontend. A companion updater replaces binaries only after the app exits and restores one previous version on startup failure.

**Tech Stack:** Go 1.27.0, Wails v2.14.0, React 19 + TypeScript generated by the Wails React template, `github.com/zalando/go-keyring` v0.2.8, `gopkg.in/yaml.v3` v3.0.1, Playwright 1.62.1, GHES REST API `2022-11-28`, Windows WebView2.

**Spec:** `../../../gitops-agent-system-design.md`

## Global Constraints

- Complete `2026-08-28-threaddock-parallel-merge.md` first.
- Support Windows 11 and 100–200% display scale.
- Keep production credentials in Windows keyring only; WSL must not receive them.
- Invoke `wsl.exe` and updater binaries with argument arrays, never shell strings.
- Poll `agentctl status --json` every 5 seconds only while the app is open.
- Use the exact selected design source `../../../opendesign/design-systems/thread-dock-product/`.
- Show all workflows; enable execution only for `workflow_dispatch` without required inputs.
- Store no full terminal transcript or Actions log.
- Do not block old application versions solely because a newer Release exists.
- Do not add an update server; GHES Releases is the only update source.
